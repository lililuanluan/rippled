# Constraint Discovery Roadmap

This project should not assume that the bug5 or bug6 constraints are known in
advance. The goal is to discover useful constraints from executions generated by
CSF itself.

## Principle

The search loop treats CSF as the ground-truth executor. Honest proposals,
validations, accepts, and ledger branches must be produced by the consensus
logic. A candidate schedule may only control external degrees of freedom such as
initial open transactions, initial raw close times, timer timings, and message
delivery choices.

Constraints are learned from traces. They are not hand-written descriptions of
known bugs.

## Data Collection

For every execution, record a structured trace:

- Initial state: per-node txset side, raw close time, previous round time, and
  establish time.
- Event order: timer ticks and the proposal deliveries that actually occurred.
- Local decision state: proposal sequence, txset position, close time, vote
  distribution, threshold, and whether the node kept, flipped, accepted, or
  moved on.
- Final result: accepted branch distribution, validation branch distribution,
  maximum exact-ledger validation count, and whether quorum was reached.

The labels should include both strict violations and near misses. Near misses
are important because true violations are sparse.

## Feature Extraction

Turn each trace into predicates that can be learned from:

- Whether initial txsets are split and how balanced the split is.
- Whether initial close times cross a rounding boundary.
- Which nodes enter establish early or late.
- Which nodes receive balanced or conflicting peer proposals before a timer
  tick.
- Whether a node's required threshold increases between two observed decisions.
- Whether proposal deliveries create asymmetric local views.
- Whether accepted or validated branches have high entropy.
- Whether an exact ledger branch reaches quorum.

These predicates should be generic. They should not mention bug-specific node
IDs unless the learner discovers that a node role is useful.

## Learning Constraints

Use interpretable learners first:

- Decision trees to identify high-value predicates.
- Sparse logistic regression to rank features.
- Association-rule mining to find combinations of predicates that predict
  near misses or violations.
- Random forests or gradient-boosted trees as a stronger predictor, followed by
  feature importance or SHAP-style explanation.

The output is a set of soft constraints, for example:

- Prefer executions where some node observes a balanced vote distribution before
  a later timer tick.
- Prefer executions where accepted branches have high entropy.
- Prefer delivery graphs that create different local majorities.
- Prefer close-time values near a rounding boundary when close-time entropy is
  predictive.

These constraints bias the sampler. They do not replace CSF validation.

## Search Loop

The intended loop is:

1. Generate schedules with random, CEM, RL, or MCTS.
2. Run each schedule in CSF.
3. Extract trace features and labels.
4. Learn predicates that distinguish near misses and violations.
5. Bias the next sampler toward satisfying the learned predicates.
6. Re-run in CSF and keep only schedules that actually violate the quorum
   property.

This is a CEGIS-style loop: propose, execute, learn from counterexamples, and
refine.

## Feasibility

The strongest version should construct schedules online. At each step, the
agent can only deliver proposals that have already been emitted by CSF and have
not already been delivered to the receiver. This makes causal feasibility a
property of the action space rather than an after-the-fact check.

Offline sampled encodings can still be useful for fast baselines, but they
should report missed delivery intents separately from actual delivered events.

## Next Steps

The practical progression should be:

1. Keep random and CEM as baselines.
2. Add online RL or MCTS where actions are chosen from currently available
   messages.
3. Add trace feature extraction for all executions.
4. Train an interpretable rule learner over success and near-miss traces.
5. Feed learned soft constraints back into the sampler.
